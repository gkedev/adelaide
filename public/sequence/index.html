ChipIn - Recommendation Agent

A demo of AAuth's federated (four-party) access model. Hellō, the person server, identifies the player. The player's conditions (brands, one case size, max cost) become a mission that downselects products across real UCP stores, enforced by Keycard as a Cedar policy. The mission ends with a ranked shortlist. Buying is the player's separate, optional choice: then ChipIn's resource token carries the exact order's hash, the auth token is proof of that order, and payment is a Stripe shared payment token capped at the total.

Trust grows tool by tool

catalog_search needs an agent token, the cart and mission_propose a person token, and mission_approve and checkout an auth token for exactly what is approved.

The mission downselects

Brands, a case size and a max cost narrow the products across Tennis Express and Holabird to a ranked shortlist. The player reviews it; nothing is bought unless they choose to.

Keycard enforces the mission

Approving the selection publishes a Cedar policy in the Keycard zone. Every order line is evaluated by Keycard: brand, case size, and the mission's total spending against the max cost.

If the player buys, the order is bound

ChipIn's resource token carries the order's SHA-256 (its offer); the auth token comes back naming the same order. ChipIn charges only that order, once, with a Stripe token capped at its total.
